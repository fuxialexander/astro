# Environment Variables

Astro uses an **env profile system** to manage configuration across three operating modes. Each mode has its own env file; you switch between them with a single command.

## How It Works

```
.env              Shared secrets (JWT keys, GitHub OAuth). Always loaded.
                  Never mode-specific. Checked into .gitignore.

.env.prod         Prod profile: remote Supabase, Fly.io backend URL, VITE_* vars.
                  Created once, edited with your credentials, never overwritten.

.env.local.dev    Dev profile: local Supabase, Cloudflare tunnel URLs.
                  Auto-generated by `npm run env:init`.

.env.local        Symlink to the active profile (or absent for local mode).
                  Vite + tsx both load .env + .env.local automatically.
```

Switching modes changes the `.env.local` symlink:

| Command | Effect | .env.local |
|---|---|---|
| `npm run env:local` | PGlite, no auth, no Supabase | Removed (absent) |
| `npm run env:dev` | Local Supabase + Cloudflare tunnel | Symlink to `.env.local.dev` |
| `npm run env:prod` | Remote Supabase + Fly.io + Cloudflare Pages | Symlink to `.env.prod` |
| `npm run env:switch` | Show current mode | No change |

## First-Time Setup

```bash
# 1. Create profile templates (one-time)
npm run env:init

# 2. Edit .env.prod with your production credentials
#    (Supabase URL, keys, Fly.io app name, etc.)

# 3. Edit .env with shared secrets
#    (JWT keys, GitHub OAuth — generate with: openssl rand -hex 32)
```

After setup, deploying is just:

```bash
npm run env:prod     # Activate prod profile
npm run deploy       # Deploys backend + frontend
```

## Deployment Flow

The deploy script (`scripts/deploy.sh`) sources `.env` + `.env.local` to get all configuration. The flow is:

1. **Edit credentials** in `.env.prod` and `.env` (one-time)
2. **Activate the profile**: `npm run env:prod`
3. **Deploy**: `npm run deploy`

If you deploy without activating the prod profile, the script will detect the wrong mode and tell you exactly what to do.

## Variable Reference

### Shared Secrets (.env)

These are mode-independent. Generate each JWT secret with `openssl rand -hex 32`.

| Variable | Required | Description |
|---|---|---|
| `RELAY_JWT_SECRET` | Production | Signs tokens for agent runner <-> relay auth. 256-bit hex. |
| `DEVICE_AUTH_JWT_SECRET` | Production | Signs access tokens for device auth flow. Must differ from above. |
| `DEVICE_AUTH_REFRESH_SECRET` | Production | Signs refresh tokens for device auth flow. Must differ from above. |
| `DATABASE_URL` | Production | Postgres connection string (Supabase pooler, port 6543). |
| `GITHUB_CLIENT_ID` | Optional | GitHub OAuth app client ID (for repo integration, not login). |
| `GITHUB_CLIENT_SECRET` | Optional | GitHub OAuth app secret. |
| `FLY_APP` | Optional | Fly.io app name (default: `astro-backend-deploy`). |
| `CLOUDFLARE_PAGES_PROJECT` | Optional | Cloudflare Pages project name (default: `astro-app`). |
| `CLOUDFLARED_DOMAIN` | Dev mode | Domain for Cloudflare tunnel (used by `env:init` to generate dev profile). |
| `TELEGRAM_BOT_TOKEN` | Optional | Telegram bot for user notifications (task completed, approvals). |
| `MONITOR_TELEGRAM_BOT_TOKEN` | Optional | Separate bot for server monitoring (falls back to `TELEGRAM_BOT_TOKEN`). See [Monitoring Guide](../guides/monitoring.md). |
| `MONITOR_TELEGRAM_CHAT_ID` | Optional | Chat ID for monitoring alerts (falls back to `TELEGRAM_CHAT_ID`). |

### Prod Profile (.env.prod)

These are loaded when `npm run env:prod` is active.

| Variable | Required | Description |
|---|---|---|
| `VITE_API_BASE_URL` | Yes | Fly.io backend URL (e.g., `https://astro-backend-deploy.fly.dev`). Baked into frontend at build time. |
| `VITE_SUPABASE_URL` | Yes | Remote Supabase project URL (e.g., `https://xxx.supabase.co`). |
| `VITE_SUPABASE_ANON_KEY` | Yes | Supabase anon/public key (starts with `eyJ...`). |
| `SUPABASE_URL` | Yes | Same as `VITE_SUPABASE_URL` (used by backend). |
| `SUPABASE_ANON_KEY` | Yes | Same as `VITE_SUPABASE_ANON_KEY` (used by backend). |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Supabase service role key (bypasses RLS, backend only). |
| `WEBAUTHN_RP_NAME` | Optional | Relying party name for passkeys (default: `Astro`). |
| `WEBAUTHN_RP_ID` | Optional | Domain for passkey auth (e.g., `astro-app.pages.dev`). |
| `WEBAUTHN_ORIGIN` | Optional | Full URL for passkey verification. |
| `FRONTEND_URL` | Optional | Frontend URL for CORS + invite links. |
| `CORS_ORIGIN` | Optional | Additional CORS allowed origin. |
| `ASTRO_BASE_URL` | Optional | Frontend URL in device auth links, emails, notifications. |

### Dev Profile (.env.local.dev)

Auto-generated by `npm run env:init`. Uses local Supabase + Cloudflare tunnel.

| Variable | Description |
|---|---|
| `VITE_SUPABASE_URL` | Local Supabase via tunnel (e.g., `https://astro-supabase.yourdomain.com`). |
| `VITE_SUPABASE_ANON_KEY` | Local Supabase anon key (auto-detected if Supabase is running). |
| `VITE_HMR_PROTOCOL` | `wss` (HMR over tunnel). |
| `VITE_HMR_HOST` | Tunnel hostname for Vite HMR. |
| `WEBAUTHN_RP_ID` | Tunnel domain (needed for passkeys over HTTPS). |
| `WEBAUTHN_ORIGIN` | Tunnel URL. |

### Local Mode (no .env.local)

When `.env.local` is absent, the app auto-detects local mode:
- Backend uses PGlite (Postgres-in-WASM, in-memory)
- No authentication, single-user
- No Supabase, no external services
- Perfect for rapid development iteration

### Frontend Build Variables (VITE_*)

Variables prefixed with `VITE_` are baked into the frontend at build time by Vite. They are NOT runtime configuration — changing them requires a rebuild.

| Variable | Default (dev) | Purpose |
|---|---|---|
| `VITE_API_BASE_URL` | (empty — Vite proxy) | Backend API URL. Empty in dev (Vite proxies `/api` to localhost:3001). Required in prod. |
| `VITE_SUPABASE_URL` | (empty — local mode) | Supabase project URL. Empty = local mode (no auth). |
| `VITE_SUPABASE_ANON_KEY` | (empty — local mode) | Supabase anon key. Empty = local mode. |

### Set by fly.toml (don't override)

| Variable | Value | Why |
|---|---|---|
| `NODE_ENV` | `production` | Enables production CORS, rate limiting, JWT validation. |
| `RELAY_PORT` | `3002` | Matches the Fly.io service port mapping. |
