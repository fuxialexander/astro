# Plan: Linear-style Project/Task/Milestone UI

## Summary

Make the project/task/milestone hierarchy work like Linear:
- **Projects** have timeline/target dates, lead, health, initiative (full Linear properties)
- **Tasks** have NO dates — they're agent-solvable work items, dates are meaningless
- **Milestones** keep dates (zero-duration checkpoints on the project timeline)
- **Project overview** is a tabbed page (Overview / Graph / Timeline / List / Updates) matching UI.pen
- **Projects list** uses real data instead of hardcoded `projectMeta`

## Files to Change

### 1. `src/types/index.ts` — Add project fields, remove task dates

**Changes:**
- Add to `Project`: `startDate?: string`, `targetDate?: string`, `lead?: string`, `health?: 'on_track' | 'at_risk' | 'off_track'`, `initiative?: string`, `progress?: number`
- Remove from `PlanNode`: `startDate?: string`, `endDate?: string` fields
- Keep `startDate`/`endDate` ONLY when `type === 'milestone'` — but since TS union discrimination on the existing flat type would be a large refactor, we'll keep the optional fields in the type but stop using them for tasks in practice

Actually, cleaner approach: keep `startDate`/`endDate` as optional on `PlanNode` (they already are) but:
- Stop generating them for tasks in the AI prompt
- Stop showing/editing them for tasks in the timeline
- Continue using them for milestones only

## Key Design Decisions

- **Tasks have no dates**: AI won't generate them, UI won't show them, timeline auto-derives positions from dependency order (existing `assignDefaultDates` logic works fine as fallback)
- **Milestones keep dates**: They're project checkpoints with real deadlines
- **Project overview = tabbed container**: Matches UI.pen exactly — Overview/Graph/Timeline/List/Updates tabs
- **Projects list**: Real data from store, grouped by initiative, with right panel
- **No breaking migration**: Optional fields remain optional, existing data gracefully handles missing dates
