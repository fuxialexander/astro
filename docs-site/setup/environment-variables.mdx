## Env Profile System

Astro uses an **env profile system** to manage configuration across three operating modes. Each mode has its own env file; switching is a single command.

```
.env              Shared secrets (JWT keys, GitHub OAuth). Always loaded.
                  Never mode-specific. Checked into .gitignore.

.env.prod         Prod profile: remote Supabase, Fly.io backend URL, VITE_* vars.
                  Created once, edited with your credentials, never overwritten.

.env.local.dev    Dev profile: local Supabase, Cloudflare tunnel URLs.
                  Auto-generated by `npm run env:init`.

.env.local        Symlink to the active profile (or absent for local mode).
                  Vite + tsx both load .env + .env.local automatically.
```

### Switching Modes

| Command | Effect | `.env.local` |
|---------|--------|-------------|
| `npm run env:local` | PGlite, no auth | Removed (absent) |
| `npm run env:dev` | Local Supabase + tunnel | Symlink to `.env.local.dev` |
| `npm run env:prod` | Remote Supabase + Fly.io | Symlink to `.env.prod` |
| `npm run env:switch` | Show current mode | No change |

### First-Time Setup

```bash
# 1. Create profile templates (one-time)
npm run env:init

# 2. Edit .env.prod with your production credentials
# 3. Edit .env with shared secrets (generate JWT keys with: openssl rand -hex 32)
```

## Variable Reference

### Shared Secrets (`.env`)

These are mode-independent. Generate each JWT secret with `openssl rand -hex 32`.

<ParamField body="RELAY_JWT_SECRET" type="string" required>
  Signs tokens for agent runner to relay authentication. 256-bit hex string. Required in production.
</ParamField>

<ParamField body="DEVICE_AUTH_JWT_SECRET" type="string" required>
  Signs access tokens for the device authorization flow. Must differ from `RELAY_JWT_SECRET`. Required in production.
</ParamField>

<ParamField body="DEVICE_AUTH_REFRESH_SECRET" type="string" required>
  Signs refresh tokens for the device authorization flow. Must differ from the above secrets. Required in production.
</ParamField>

<ParamField body="DATABASE_URL" type="string" required>
  Postgres connection string (Supabase pooler, port 6543). Required in production.
</ParamField>

<ParamField body="GITHUB_CLIENT_ID" type="string">
  GitHub OAuth app client ID for repository integration (not login). Optional.
</ParamField>

<ParamField body="GITHUB_CLIENT_SECRET" type="string">
  GitHub OAuth app secret. Optional.
</ParamField>

<ParamField body="FLY_APP" type="string" default="astro-backend-deploy">
  Fly.io app name used by the deploy script.
</ParamField>

<ParamField body="CLOUDFLARE_PAGES_PROJECT" type="string" default="astro-app">
  Cloudflare Pages project name used by the deploy script.
</ParamField>

<ParamField body="CLOUDFLARED_DOMAIN" type="string">
  Domain for Cloudflare tunnel. Used by `env:init` to generate the dev profile. Required for dev mode.
</ParamField>

<ParamField body="TELEGRAM_BOT_TOKEN" type="string">
  Telegram bot token for user notifications (task completed, approvals). Optional.
</ParamField>

### Prod Profile (`.env.prod`)

Loaded when `npm run env:prod` is active.

<ParamField body="VITE_API_BASE_URL" type="string" required>
  Fly.io backend URL (e.g., `https://astro-backend-deploy.fly.dev`). Baked into frontend at build time.
</ParamField>

<ParamField body="VITE_SUPABASE_URL" type="string" required>
  Remote Supabase project URL (e.g., `https://xxx.supabase.co`).
</ParamField>

<ParamField body="VITE_SUPABASE_ANON_KEY" type="string" required>
  Supabase anon/public key (starts with `eyJ...`).
</ParamField>

<ParamField body="SUPABASE_URL" type="string" required>
  Same as `VITE_SUPABASE_URL` — used by the backend.
</ParamField>

<ParamField body="SUPABASE_ANON_KEY" type="string" required>
  Same as `VITE_SUPABASE_ANON_KEY` — used by the backend.
</ParamField>

<ParamField body="SUPABASE_SERVICE_ROLE_KEY" type="string" required>
  Supabase service role key. Bypasses RLS — backend only. Never expose to the frontend.
</ParamField>

<ParamField body="WEBAUTHN_RP_NAME" type="string" default="Astro">
  Relying party name displayed during passkey registration.
</ParamField>

<ParamField body="WEBAUTHN_RP_ID" type="string">
  Domain for passkey auth (e.g., `astro-app.pages.dev`).
</ParamField>

<ParamField body="WEBAUTHN_ORIGIN" type="string">
  Full URL for passkey verification.
</ParamField>

<ParamField body="FRONTEND_URL" type="string">
  Frontend URL for CORS and team invite links.
</ParamField>

<ParamField body="CORS_ORIGIN" type="string">
  Additional CORS allowed origin.
</ParamField>

<ParamField body="ASTRO_BASE_URL" type="string">
  Frontend URL used in device auth links, emails, and notifications.
</ParamField>

### Dev Profile (`.env.local.dev`)

Auto-generated by `npm run env:init`. Uses local Supabase + Cloudflare tunnel.

| Variable | Description |
|----------|-------------|
| `VITE_SUPABASE_URL` | Local Supabase via tunnel |
| `VITE_SUPABASE_ANON_KEY` | Local Supabase anon key (auto-detected) |
| `VITE_HMR_PROTOCOL` | `wss` (HMR over tunnel) |
| `VITE_HMR_HOST` | Tunnel hostname for Vite HMR |
| `WEBAUTHN_RP_ID` | Tunnel domain |
| `WEBAUTHN_ORIGIN` | Tunnel URL |

### Local Mode (no `.env.local`)

When `.env.local` is absent, the app auto-detects local mode:
- Backend uses PGlite (Postgres-in-WASM)
- No authentication, single-user
- No Supabase, no external services

### Frontend Build Variables (`VITE_*`)

<Warning>
  Variables prefixed with `VITE_` are baked into the frontend at build time by Vite. They are NOT runtime configuration — changing them requires a rebuild.
</Warning>

| Variable | Default (dev) | Purpose |
|----------|--------------|---------|
| `VITE_API_BASE_URL` | _(empty, Vite proxy)_ | Backend API URL. Empty in dev (Vite proxies `/api`). Required in prod. |
| `VITE_SUPABASE_URL` | _(empty, local mode)_ | Supabase project URL. Empty = local mode. |
| `VITE_SUPABASE_ANON_KEY` | _(empty, local mode)_ | Supabase anon key. Empty = local mode. |

### Set by `fly.toml` (do not override)

| Variable | Value | Why |
|----------|-------|-----|
| `NODE_ENV` | `production` | Enables production CORS, rate limiting, JWT validation |
| `RELAY_PORT` | `3002` | Matches the Fly.io service port mapping |
