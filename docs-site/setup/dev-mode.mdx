## Overview

Dev Mode runs a full multi-user stack locally using Docker-hosted Supabase for authentication and data persistence, plus a Cloudflare tunnel for HTTPS (required for WebAuthn/passkey login).

| Aspect | Dev Mode |
|--------|---------|
| **Database** | Local Supabase (Postgres in Docker) |
| **Auth** | WebAuthn passkeys via Cloudflare tunnel (HTTPS) |
| **External services** | Docker, Cloudflare tunnel |
| **Multi-device sync** | Yes (Supabase Realtime) |
| **Team features** | Yes |
| **Best for** | Testing auth flows, multi-user features, RLS policies |

## Prerequisites

Before starting dev mode, you need:

1. **Docker Desktop** — [Install Docker](https://docker.com/products/docker-desktop) and ensure it's running
2. **Supabase CLI** — `npm install -g supabase`
3. **Cloudflare account** with a domain configured — for HTTPS tunneling
4. **`cloudflared` CLI** — [Install cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/)

## Quick Start

<Steps>
  <Step title="One-time setup: generate env profiles">
    ```bash
    npm run env:init
    ```

    This creates `.env.local.dev` with template values for your Cloudflare tunnel domain.
  </Step>
  <Step title="Configure your tunnel domain">
    Edit `.env` and set your Cloudflare tunnel domain:

    ```bash
    CLOUDFLARED_DOMAIN=yourdomain.com
    ```

    Then re-run `npm run env:init` to regenerate the dev profile with the correct tunnel URLs.
  </Step>
  <Step title="Start everything">
    ```bash
    npm run dev:dev
    ```

    This command:
    1. Switches the environment to dev mode (symlinks `.env.local` → `.env.local.dev`)
    2. Starts local Supabase via Docker
    3. Starts the Cloudflare tunnel
    4. Starts Vite + Hono + WebSocket relay
  </Step>
  <Step title="Verify">
    Open your tunnel URL (e.g., `https://astro.yourdomain.com`). You should see the login page with passkey registration.
  </Step>
</Steps>

## Architecture

```
Browser (https://astro.yourdomain.com)
    ↓ HTTPS via Cloudflare Tunnel
Vite dev server (localhost:5173)
    ↓ Proxy /api → localhost:3001
Hono API server (localhost:3001)
    ↓ Postgres connection
Local Supabase (Docker, localhost:54321)
    - PostgreSQL (port 54322)
    - Auth (port 54321)
    - Realtime (port 54321)
    - Studio (port 54323)
```

### Cloudflare Tunnel Routes

The tunnel script creates four routes for local services:

| Route | Local Port | Service |
|-------|-----------|---------|
| `astro.yourdomain.com` | 5173 | Vite frontend |
| `astro-api.yourdomain.com` | 3001 | Hono API |
| `astro-relay.yourdomain.com` | 3002 | WebSocket relay |
| `astro-supabase.yourdomain.com` | 54321 | Supabase API |

## Local Supabase

### Starting Supabase Independently

If you need to manage Supabase separately:

```bash
# Start local Supabase
npx supabase start

# Check status
npx supabase status

# Stop
npx supabase stop
```

### Supabase Studio

Access the local Supabase dashboard at [http://localhost:54323](http://localhost:54323) to:

- Browse tables and data in the Table Editor
- Manage authentication users
- View real-time subscriptions
- Test RLS policies

### Applying Migrations

```bash
# Push migrations to local Supabase
npx supabase db push

# Check migration status
npx supabase migration list
```

## Environment Variables

The dev profile (`.env.local.dev`) is auto-generated by `npm run env:init` and contains:

| Variable | Description |
|----------|-------------|
| `VITE_SUPABASE_URL` | Local Supabase via tunnel (e.g., `https://astro-supabase.yourdomain.com`) |
| `VITE_SUPABASE_ANON_KEY` | Local Supabase anon key (auto-detected if Supabase is running) |
| `VITE_HMR_PROTOCOL` | `wss` (HMR over tunnel) |
| `VITE_HMR_HOST` | Tunnel hostname for Vite HMR |
| `WEBAUTHN_RP_ID` | Tunnel domain (needed for passkeys over HTTPS) |
| `WEBAUTHN_ORIGIN` | Tunnel URL |

Shared secrets (JWT keys, GitHub OAuth) go in `.env`, which is loaded in all modes.

## Why HTTPS Is Required

WebAuthn (passkey authentication) requires a [secure context](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts):
- `localhost` works (treated as secure by browsers)
- Any other hostname requires HTTPS
- Touch ID / Face ID registration and verification fail over plain HTTP

The Cloudflare tunnel provides HTTPS for your local dev environment, making passkey auth work on any device on your network.

## Testing Auth Flows

<Steps>
  <Step title="Register a new user">
    Open the tunnel URL and click **Register**. Follow the passkey registration flow (Touch ID, Face ID, or security key).
  </Step>
  <Step title="Verify in Supabase Studio">
    Open [http://localhost:54323](http://localhost:54323) → Authentication → Users. Your new user should appear.
  </Step>
  <Step title="Test multi-device sync">
    Open the app in two browsers or devices. Changes made in one should appear in the other via Supabase Realtime.
  </Step>
</Steps>

## Switching Modes

```bash
npm run env:local   # Switch to local mode (PGlite, no auth)
npm run env:prod    # Switch to production mode
npm run env:switch  # Show current mode
```

## Troubleshooting

<Accordion title="Docker not running">
  - Ensure Docker Desktop is running
  - Run `docker ps` to verify Docker is accessible
  - On Linux, ensure your user is in the `docker` group
</Accordion>

<Accordion title="Tunnel not connecting">
  - Verify `cloudflared` is installed: `cloudflared --version`
  - Check your Cloudflare domain is configured with the tunnel
  - Run `bash scripts/start-tunnel.sh` manually to see tunnel output
</Accordion>

<Accordion title="Passkey registration fails">
  - Ensure you're accessing the app via the HTTPS tunnel URL, not `localhost`
  - Check that `WEBAUTHN_RP_ID` and `WEBAUTHN_ORIGIN` match your tunnel domain
  - Clear browser passkey cache if switching between domains
</Accordion>
