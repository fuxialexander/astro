## Plan Graph

The heart of Astro is the **plan graph** — a directed acyclic graph (DAG) where nodes are tasks and edges are dependencies.

Unlike flat lists (Linear issues, GitHub Projects), the plan graph:
- Supports **branching exploration trees** (multiple hypotheses running in parallel)
- Enforces **explicit dependencies** (task B cannot start until task A completes)
- Enables **branch pruning** (cancel a dead-end branch and all downstream tasks are auto-cancelled)

```
Goal
├── Milestone A
│   ├── Task 1 (planned)
│   └── Task 2 (depends on Task 1)
├── Branch B (hypothesis / feature track)
│   ├── Task 3 (in progress)
│   └── Task 4 (blocked)
└── Branch C (pruned — dead end)
    └── Task 5 (auto-cancelled)
```

See [Plan Graph](/features/plan-graph) for full details.

## Vision Document

Each project has a **vision document** — a persistent, editable description of:
- The product goal or research question
- Key design principles or analytical frameworks
- Decisions made so far

This document is **injected into every agent session**, providing product-level context above what agents pick up from the codebase. It's the missing link between high-level intent and low-level execution.

## Dependency-Aware Dispatch

When a task's dependencies are satisfied, Astro automatically dispatches it to an available machine. Tasks without dependencies on each other run **in parallel** across multiple machines.

Supported execution environments:
- **Local machine** — your laptop or desktop via the agent runner
- **HPC cluster** — Slurm-managed compute nodes
- **Cloud** — AWS, GCP, or any machine reachable over the network

## Tiered Verification

Not every task needs human review. Astro supports three verification tiers:

| Tier | Trigger | Human Action |
|------|---------|-------------|
| **Auto-close** | Tests pass, build succeeds, analysis produces expected output | Notification only |
| **Judgment** | Result needs strategic evaluation | Review summary, approve/reject |
| **Strategic decision** | Fork in the plan requiring direction choice | Choose which branch to pursue |

Over time, as automated verification improves, more tasks auto-close and your attention concentrates on the decisions that only you can make.

## Streaming Event Persistence

All agent activity is streamed in real-time **and** persisted to the database. This means:
- Page refreshes don't lose activity history
- SSE reconnects catch up automatically from the last seen sequence number
- Multiple team members can see the same live activity

## Machine Registry

Machines (laptops, HPC nodes, cloud instances) register with the Astro relay server. The relay:
- Maintains live WebSocket connections to registered machines
- Routes task dispatch to the correct machine
- Reports machine status (online, busy, offline)
- Cleans up ghost entries on restart

## Feature Flags

Astro uses a feature flag system to roll out new features safely:
- Internal teams get early access
- External users see nothing until the feature is released (GA)
- Emergency kill switches disable features instantly without deployment

See [Setup & Deployment](/setup/production) for flag management.
